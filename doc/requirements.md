# SimpleMarkdownEditor 要求書

最終更新: 2026-09-06（実装に合わせて全面改訂）

## 1. 概要

SimpleMarkdownEditor は、Markdown テキストをリアルタイムにプレビューしながら編集できるデスクトップアプリケーションである。
Python / PySide6 (Qt 6) で実装され、macOS および Windows で動作する。

本書は Python 版（`Python/`）の要求を定義する。実装レベルの詳細は [Python/doc/SPEC.md](../Python/doc/SPEC.md) を参照。

---

## 2. 動作環境

| 項目 | 要件 |
|---|---|
| OS | macOS 12 以降 / Windows 10 以降 |
| Python | 3.10 以降 |
| 依存ライブラリ | PySide6 ≥ 6.10 かつ < 6.12、markdown ≥ 3.5、pygments ≥ 2.17 |
| Java | PlantUML を使用する場合のみ必要（同梱 `vendor/plantuml.jar` の実行用） |
| ネットワーク | 不要。Mermaid / elkjs は `vendor/` に同梱したものをインライン展開する（同梱ファイルが無い場合のみ CDN にフォールバック） |

## 3. 機能要件

### 3.1 エディタ

| ID | 要件 |
|---|---|
| ED-01 | プレーンテキストとして Markdown を入力できること |
| ED-02 | 行番号ガターを左端に常時表示すること |
| ED-03 | 水平スクロールを有効にし、行の折り返しを行わないこと |
| ED-04 | タブ幅はスペース 2 文字分とすること |
| ED-05 | カーソル位置（行・列）をステータスバーにリアルタイム表示すること |
| ED-06 | 文字数・単語数をステータスバーにリアルタイム表示すること |
| ED-07 | 現在の文字コード・改行コードをステータスバーに表示し、クリックで変更できること |

### 3.2 リアルタイムプレビュー

| ID | 要件 |
|---|---|
| PV-01 | エディタの内容変更から 300 ms 後にプレビューを自動更新すること（デバウンス処理） |
| PV-02 | プレビューはエディタと左右に並べて表示すること（スプリッター分割） |
| PV-03 | スプリッターをドラッグしてエディタ・プレビューの幅比率を変更できること |
| PV-04 | エディタのスクロール位置（比率）をプレビューに追従させること（エディタ → プレビューの一方向） |
| PV-05 | プレビュー内の http/https リンクはシステムブラウザで開き、ローカルの `.md` リンクはエディタのタブで開くこと |

| MD-06 | 引用ブロックをレンダリングすること | `> 引用` |

### 3.9 外部変更の検知とリロード

| ID | 要件 |
|---|---|
| FR-01 | 開いているファイルが他のエディタ等で変更されたことを検知できること |
| FR-02 | ネットワーク共有（Windows の UNC パス・ネットワークドライブ）上のファイルでも検知できること。OS の変更通知に依存せず、定期的なファイル状態の確認を併用すること |
| FR-03 | 自アプリによる保存を外部変更として誤検知しないこと |
| FR-04 | 他エディタが「一時ファイル作成 + rename」で保存した場合も、以後の変更を検知し続けること |
| FR-05 | 外部変更を検知した場合、既定ではバナーで通知するだけとし、ユーザーの操作なしにエディタの内容を置き換えないこと |
| FR-06 | 「自動で再読み込み」を選択した場合でも、未保存の変更があるときは自動で置き換えず通知にとどめること |
| FR-07 | 開いているファイルを任意のタイミングでディスクの内容に再読み込みできること。ツールバーのボタン・File メニュー・`F5` / `Ctrl+R` のいずれからも実行でき、未保存の変更がある場合は破棄確認を表示すること |
| FR-08 | 再読み込み時はカーソル行・列およびスクロール位置を維持すること |
| FR-09 | ファイルが削除された、または共有がオフラインの場合は、編集中の内容を保持し破棄しないこと |
| FR-10 | ファイル状態の確認に時間がかかる（共有が応答しない）場合は確認間隔を延ばし、操作を妨げないこと |

## 4. 非機能要件

| ID | 要件 |
|---|---|
| NF-01 | エディタへの入力からプレビュー更新までのレイテンシは 300 ms 以内（デバウンス後）とすること |
| NF-02 | ライト・ダーク両テーマで、UI 要素のコントラスト比が十分に確保されていること |
| NF-03 | macOS・Windows の両プラットフォームで同一のソースコードが動作すること |
| NF-04 | ネットワーク未接続環境でも全機能が動作すること（Mermaid / elkjs / PlantUML を同梱） |
| NF-05 | ネットワーク共有上のファイル・フォルダを扱う場合も、通常操作（入力・タブ切り替え・ツリー表示）で UI が体感できるほど停止しないこと。ファイル走査は 1 エントリあたりの問い合わせ回数を最小にすること |
| NF-06 | ファイルの読み書きに失敗した場合（共有断・権限エラー等）は、異常終了せずエラーを表示すること |
| NF-07 | ユーザーが明示的に指示しない限り、未保存の編集内容を失わないこと |

> **既知の制限**: ファイル入出力と PlantUML のレンダリングは GUI スレッドで同期実行しているため、
> 共有が応答しない場合は OS のタイムアウトまでウィンドウが応答しなくなる。非同期化は未対応
> （[Python/doc/SPEC.md](../Python/doc/SPEC.md) の「既知の制限・注意事項」参照）。

## 5. ビルド要件

| ID | 要件 |
|---|---|
| BL-01 | `build.sh` を実行することで、macOS 向け `.app` バンドルを生成できること |
| BL-02 | `build.sh` を Git Bash（Windows）で実行することで、Windows 向け `.exe` を生成できること |
| BL-03 | `build_windows.bat` を実行することで、CMD / PowerShell からも Windows 向け `.exe` を生成できること |
| BL-04 | 既定は `--onedir` ビルドとし、`--onefile` オプションも提供すること（`--onefile` は PySide6 の LGPL 要件を満たせない可能性があるため非推奨。[Python/doc/DISTRIBUTION.md](../Python/doc/DISTRIBUTION.md) 参照） |
| BL-05 | `--clean` オプションでビルド成果物（`build/`・`dist/`）を削除してからビルドできること |
| BL-06 | PyInstaller が未インストールの場合、ビルドスクリプトが自動でインストールすること |
| BL-07 | `vendor/`（mermaid.min.js / elk.bundled.js / plantuml.jar / VERSIONS.json）を実行ファイルに同梱すること |
| BL-08 | ビルド時に `vendor/` の同梱ファイルが無い場合、取得スクリプト（`update_mermaid.py` / `update_elk.py`）を自動実行すること |

> `plantuml.jar` のみ配布物のルート直下（`sys._MEIPASS` 直下）に配置する。実行時の参照先がそこであるため
> （[main_window.py `_puml_jar_path()`](../Python/main_window.py#L27-L31)）。
